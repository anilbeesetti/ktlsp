# T017c1 / #67 nesting metadata

`nesting::decode(&ClassFile) -> Result<Nesting, Error>` interprets class-level
InnerClasses, EnclosingMethod, NestHost and NestMembers against
[JVMS 23 chapter 4](https://docs.oracle.com/javase/specs/jvms/se23/html/jvms-4.html),
§§4.7.6–7 and 4.7.28–29. Source code is independently authored Rust; it reuses the
existing reader's name/descriptor validators without changing its behavior.
The only shared edit is the additive module export. No dependencies or lockfile
changes; no server caller/capability is added. Parent #17 remains open.

Returned records preserve original CP indices, optional-zero meanings, table order,
inner access flags (including reserved bits), and borrowed lossless UTF-16 binary
names/method descriptors. Existing class/member flags and raw attributes remain
unchanged in ClassFile. A member entry supplies an outer class; local/anonymous
entries have no member owner. A zero simple-name index denotes anonymous metadata,
and EnclosingMethod separately identifies lexical enclosure, including initializer
contexts with a zero method index. No dollar/name heuristic is used. Nest access
declarations do not establish lexical enclosure or resolved/authorized membership.
Duplicate/self NestMembers entries and self NestHost are retained under JVMS rules.

Validation checks exact payload lengths, class-only contexts (and ACC_MODULE's
allowlist: InnerClasses alone among these attributes), attribute uniqueness,
typed/nonzero CP references and their name/descriptor targets, constructor return
types, original Java23 version ceiling, InnerClasses introduction at 45.3,
EnclosingMethod at 49.0 and nest attributes at 55.0. For major >=51, an anonymous
entry must have zero outer index. NestHost and NestMembers cannot coexist.

Local consistency policy rejects duplicate InnerClasses binary identities (including
different CP indices naming the same class), self/cyclic lexical ownership, and a
current class claiming both member ownership and EnclosingMethod. Validation is
iterative with visited states, never recursively resolving classes. These local
contradiction checks are stricter than the JVM's limited cross-class attribute
checking. External classes, missing entries that would require source/linkage
knowledge, actual access control, flag-combination verification, bytecode and
unrelated opaque attribute interiors are deferred. UTF-16 surrogates stay lossless;
the reader deliberately does not require Unicode scalar strings.

One operation budget covers 65,535 aggregate pool slots/interfaces/members/
attributes/decoded table entries, 16 MiB UTF-16 pool storage plus raw attribute
payloads, and 64 Mi validation units of referenced text/relationship traversal.
The decoded-storage byte cap can reject a class that fits the base reader's encoded
byte cap. Unknown attributes are not decoded but their payload/name/record costs
count. Publicly constructed models cannot bypass targeted index/type/version/
size checks; this decoder is not a complete revalidation of unrelated CP entries
or member descriptors. Repeated references consume work again, including hashed
identity and graph visits. Checked addition precedes counter growth; u2 table
counts and fixed widths make table length arithmetic bounded before allocation.
