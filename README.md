# ktlsp

A Rust-only Kotlin language server under development, targeting feature parity with official `kotlin-lsp/v263.6379.0`. Full parity has **not** been achieved.

## Build and run

The repository pins Rust 1.99.0. With Rust/rustup and the platform linker installed:

```sh
cargo build --locked --release -p ktlsp-server -p ktlsp-parser --bins
./target/release/ktlsp
```

Install `ktlsp` and `ktlsp-parser-worker` from the same build together in one trusted directory. With no arguments or explicit `--stdio`, `ktlsp` reads and writes Content-Length-framed LSP on stdio. Configure an editor's server command to that executable with either launch form. Without the matching sibling worker, syntactic document symbols are unavailable; synchronization, folding and lexical diagnostics remain available. Use `--help` or `--version` for CLI output. Core operation needs no JVM or JDK. See [distribution trust and provider limits](crates/ktlsp-server/README.md).

UTF-16 remains the mandatory fallback even when a client lists only other encodings. Legacy clients receive replacement lexical/structural push diagnostics; close clears them. Clients advertising `textDocument.diagnostic` instead negotiate always-full lexical/structural pull reports without duplicate push notifications. With the trusted matching parser worker, bounded syntactic document symbols support hierarchical and flat client profiles. Compiler diagnostics, resolved navigation and other semantic providers remain unimplemented. See the [pull diagnostic contract](docs/specs/server-foundation.md#lexical-pull-diagnostics) and [syntactic symbol contract](crates/ktlsp-server/README.md#bounded-syntactic-document-symbols).

## Experimental macOS server check

At frozen `50bef1c6`, a separately reviewed observation on macOS 27.0.1 arm64 with pinned Rust 1.99.0 ran the build, version and server-package test operations below once, using an isolated target directory for the saved executable:

```sh
cargo build --locked --release -p ktlsp-server --bin ktlsp
./target/release/ktlsp --version
cargo test --locked -p ktlsp-server
```

**Known build-child failure:** `rust-objcopy` aborted with SIGABRT because dyld could not load `@rpath/libLLVM.dylib`; debug-info stripping failed even though Cargo exited 0. The release executable reported its version, and 38 server-only tests passed (12 provider, 16 session, 10 stdio). This is bounded package evidence at `50bef1c6`, not current-source/workspace/parser/dependency-crate tests, editor/performance validation or full Mac support. At that historical freeze the server had no parser dependency; the current optional symbol provider does. [#96](https://github.com/anilbeesetti/ktlsp/issues/96) remains OPEN/UNKNOWN; do not run the current unqualified server suite locally because it now includes real parser consumers. See the durable [Mac observation receipt](docs/status/development.md#bounded-mac-server-observation) for provenance and limits.
