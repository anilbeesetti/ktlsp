# Explicit project model v2 (T021b / #78)

`ktlsp_project::v2::{from_json, load_manifest}` return a separate
`v2::ProjectModel` or `v2::Error`. The v1 types, loaders, unknown-field policy
and compile/non-exported library strings are unchanged. Neither loader accepts
the other schema version. There is no v2-to-v1 conversion or consumer migration.

The independently authored [contract example](fixtures/t021b/contract-example.json)
uses `schemaVersion: 2`. Required fields: schemaVersion, modules, each module id,
each dependency type/target/scope, each source root path/kind, and each library
id/binaries. Other collections default empty; exported/generated default false;
languageSettings defaults unset. Unknown fields, duplicate JSON fields, unknown
tags/scopes, malformed JSON and ill-typed values reject.

Each module has one ordered `dependencies` list containing tagged objects:

```json
[
  {"type":"module","module":"core","scope":"compile","exported":false},
  {"type":"library","library":"stdlib","scope":"test","exported":true}
]
```

Both variants accept compile/test/runtime/provided and exported false/true.
Edge identity is the tuple (tag, target, scope, exported). Identical tuples in
one module reject; different scopes or export values remain separate and in
their declared positions, including parallel module edges. Module and ordinary
project-library IDs occupy separate namespaces. All targets must resolve;
module self-edges and cycles anywhere in the graph reject across all scopes and
export values. The loader validates declared structure, not semantic visibility.
The [ordered fixture](fixtures/t021b/ordered.json) exercises all eight library
scope/export tuples and interleaved module edges with same-name namespaces.

SourceRoot, LanguageSettings, Library and SDK archive concepts retain the v1
validation rules. Internally, common fields move through the existing private
validator without translating dependency edges. Paths are absolute Unicode
native-platform paths normalized lexically against the manifest parent, retaining
missing artifacts and parent-relative paths. Empty/NUL/non-UTF-8 manifest paths
reject, including relative paths under a non-UTF-8 working directory. Root
ownership checks are lexical; symlink aliases need later filesystem validation.
Path normalization is the declared semantics: original relative spelling and
omitted defaults are not retained. Compact `serde_json` serialization of an
unchanged loader-returned model can be reparsed losslessly, preserving resolved
data and dependency identity/scope/exports/order. Before returning, the loader
counts the normalized model's actual compact serialized bytes (including Unicode
and JSON escaping) without storing output. Above 2 MiB it rejects explicitly with
`NormalizedOutputBudgetExceeded`; short input can therefore reject after path or
default expansion. No data is truncated or coalesced to fit. Pretty printing and
caller mutation of public fields can exceed the input budgets.

The unchanged streaming preflight enforces limits before typed allocation:
2 MiB bytes, 4,096 modules, 8,192 libraries, 65,536 combined dependency edges,
16,384 source roots and 32,768 binary/source/SDK paths. File reads take at most
the byte limit plus one sentinel. JSON's default depth bound remains enabled;
the whole module graph uses iterative Kahn traversal, and common ownership
validation sorts roots and uses an ancestor stack. All limits apply together:
65,536 well-formed tagged edges cannot fit in 2 MiB. Tests distinguish the exact
preflight edge-count boundary (compact malformed entries) from a valid 16,385-edge
mixed graph that fits the byte limit.

V2 additionally limits the caller manifest path and aggregate estimated expanded
path bytes to 8 MiB (`v2::MAX_EXPANDED_PATH_BYTES`). Before any model path joins,
the estimate counts the base plus separator for each relative path and each
root-only path whose join retains a prefixed base, across all
root/binary/source/SDK collections. Other absolute paths count only their own bytes.
This conservative limit can reject paths whose later `..` normalization would
shrink them. It prevents a caller-supplied long base from multiplying unbounded
allocation across many short paths, and reports `ExpandedPathBudgetExceeded`.
V1 has separate [caller and expansion guards](reviews/t111-v1-path-budget.md);
its serialization/reload behavior retains no normalized-output cap.

Focused retained-prefix tests freeze exact 8 MiB admission (which can then hit
the separate 2 MiB output cap), one-byte-over rejection, aggregate-before-graph
precedence and small resolved-path controls. Cygwin absolute root-only paths
distinguish the accounting defect; Windows rooted paths are preservation controls.
These platform cases are source-reviewed; Linux checks do not execute them or
establish Cygwin/Windows runtime correctness.

## SDK catalog and dependency data (#342 / #330 / #21)

V2 also accepts an ordered `sdks` catalog (default empty). The canonical public
`v2::Sdk` record uses `name`, `type`, required nullable `version` and `homePath`,
optional nullable `roots` (absent equals null, distinct from `[]`), and required
opaque string `additionalData`. Empty version/additionalData strings are retained;
identity/root type strings must be nonempty, and all SDK strings reject NUL.
Each ordered root requires `url` and `type`; custom root types are retained.
Catalog identity is `(name,type)`, not name alone. Duplicate identities reject;
same names with different types and module/library names remain separate.

Dependencies additionally accept `{"type":"sdk","name":"JDK","kind":"JavaSDK"}`
and `{"type":"inheritedSdk"}` in their declared positions. Explicit references
must match both catalog identity components. Repeated explicit identity or
inherited marker in one module rejects; explicit plus inherited is retained
without selecting an effective SDK. These edges have no scope/export field and
never become library/archive edges. Unknown fields and malformed types reject.

Home strings retain their exact spelling and nullability. Only absolute
host-native paths or `<WORKSPACE>/` spellings are admitted, without backslashes,
other placeholders, URL syntax or NUL. Unlike ordinary model paths, SDK homes
are not normalized, joined to the manifest base, probed or used to derive roots.
Root URLs retain exact spelling/order, including legacy `jrt://...!/modules/`;
they require a nonempty scheme/`://` payload and reject whitespace, controls and
backslashes. This is bounded URL-envelope validation, not virtual filesystem,
archive/percent decoding, canonicalization or URL-target validation.

Streaming preflight additionally caps SDK records at 8,192 and total SDK roots at
32,768 before typed allocation. SDK decoded string bytes are capped at 2 MiB;
the manifest byte/serialized-output ceilings apply simultaneously. These are
logical collection/work/storage bounds, not allocator/RSS guarantees.

No default SDK selection, inherited-SDK resolution, root discovery from homes,
legacy-jrt rewriting, symlink/foreign-platform compatibility, additionalData XML
interpretation, build/network/archive execution or semantic visibility is added.
The official importer-v2 retains this data with the same canonical record; strict
v1 still refuses SDK semantics. Resources/exclusions, facets/plugins/compiler/
output/build settings and official path parity remain pending. Parent T021/#21
stays open; this finite data contract is not SDK symbol or full-import parity.
