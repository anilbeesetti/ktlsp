Research precedes specification and implementation. Target full official Kotlin LSP parity while retaining a Rust-only server/build with no bundled Java; optional existing JDK/build tools are user-authorized. Preserve the completed research and specifications. Admit dependency-ready work against discovered environment capacity, reserving two independent reviewers per owner. Reported collaboration slots are not measured project-chat throughput; current admission, ownership and evidence are recorded in [the development ledger](status/development.md). More ticket count does not remove the semantic engine dependency chain.

1. Pin sources/releases, audit feature contracts and compiler/project dependencies, and record unknowns. Review the research/specification before coding.
2. Establish repository, Cargo workspace, native-only CI and small foundational tickets: UTF-16 text, framed transport, lossless lexer, explicit project model. These are delivered at checkpoint `0d54973`; retain their native regression coverage.
3. Integrate a runnable stdio server with lifecycle/document synchronization and honest capabilities (delivered T005). T006 is delivered in PR73: token-aware folding and explicitly lexical/structural push diagnostics over real stdio. Full folding remains partial; the recorded official fixture has deliberate field differences. Document symbols require declaration support in T008/T027; folding does not establish symbol or semantic support.
4. PR75 delivers bounded isolated parser safety only, with a 64 KiB ceiling versus 8 MiB documents and cumulative allocation cap rather than RSS. PR92 delivers immutable revisioned result validation and a bounded declaration corpus; PR90/#87 repairs ordinary parameter boundaries and PR102/#100 repairs bounded simple class/interface generic sibling functions; the historical `ab00d555` #83 audit (32 PROVED/10 GAP/3 UNVERIFIED) is not recalculated here; delivered PR106 C12 assertions and PR109 C17 known-defect fixtures do not repair recovery, while broader recovery/B3–B5/B11 evidence remains incomplete, keeping #7/#83 open and T008/T008a on HOLD; complete grammar/recovery and stable HIR/scopes/imports remain pending. Begin semantics with declarations and types; expand with constraint solving, overloads, CFG/smart casts and library symbols. Treat each language chapter as its own accepted corpus.
5. Build pure-Rust binary metadata, Java interoperability, native dependency/project imports. PR72 delivers bounded classfile structure and PR79 adds bounded declaration-annotation data decoding; PR80 adds depth-32 Java Signature ASTs, PR81 adds nesting/enclosing data and PR98 adds pinned Metadata header/d1 decoding, without linkage/access control/protobuf/name/type semantics; PR76 delivers a data-only pinned exported-model subset with an ordered sidecar and explicit v1 projection. PR84 adds separate structured v2 edges without importer migration or semantic visibility. PR74 delivers offline Maven-layout bytes/provenance and PR93 adds caller-SHA integrity without ZIP validity/authentication/resolver semantics. These foundations have no server consumers. Surface dynamic Gradle/Maven and plugin gaps rather than guessing resolved models; implement optional native orchestration of user-existing tools.
6. Implement semantic completion/navigation/diagnostics, then safe refactoring/import actions/formatting and hierarchies/hints. Audit official custom protocols and run/debug boundary.
7. Differentially validate the pinned release, tune incremental performance, package native cross-platform binaries, and publish a row-by-row parity report. PR70 delivers optional recorded-observation replay, retaining genuine differences; PR94 adds bounded synthetic-only raw capture, while fresh official execution/full corpus remain pending. PR77 historical baseline evidence and PR120 provenance correction do not validate current-main performance. Full parity remains pending until semantic, external-tool import/debug and oracle gaps are resolved.

Every implementation ticket must have a small concrete result, dependencies, ownership, tests, two independent reviews and a PR. Implementers open/attach their passing PRs and report exact reviewed SHA/URL/check evidence to root. Merge requires the coordinator's exclusive merge-window grant and expected reviewed head after hosted CI and integration checks pass. Dependencies are merged before dependent implementation or integration starts. Shared Cargo.lock integration is serialized through that gate. The delivery steward keeps the matrix and ledger current from reviewed evidence; the coordinator verifies integrated main.

No date estimate or claim of perfect behavior is justified yet. A useful native server can be delivered incrementally; the entire IntelliJ/compiler feature surface cannot be declared complete from initial syntax features. Faster or lower-memory claims require equivalent supported workloads, recorded hardware/toolchain/profile and reproducible measurements against the pinned official release.
