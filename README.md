# ktlsp

A Rust-only Kotlin language server under development, targeting feature parity with official `kotlin-lsp/v263.6379.0`. Full parity has **not** been achieved.

## Build and run

The repository pins Rust 1.99.0. With Rust/rustup and the platform linker installed:

```sh
cargo build --locked --release -p ktlsp-server -p ktlsp-parser --bins
./target/release/ktlsp
```

Install `ktlsp` and `ktlsp-parser-worker` from the same build together in one trusted directory. With no arguments or explicit `--stdio`, `ktlsp` reads and writes Content-Length-framed LSP on stdio. Configure an editor's server command to that executable with either launch form. Without the matching sibling worker, syntactic symbols, finite navigation, local completion and local-val rename are unavailable; synchronization, folding, lexical diagnostics, negotiated lexical tokens and the negotiated structural quickfix remain available. Use `--help` or `--version` for CLI output. Core operation needs no JVM or JDK. See [distribution trust and provider limits](crates/ktlsp-server/README.md).

For an explicit tiny source project and generic LSP client configuration, see
[basic native candidate setup (#430)](crates/ktlsp-server/README.md#basic-native-candidate-setup-430).
This is source/setup guidance, not visual-editor verification or a ready release:

current-source archives await ROOT's guarded acceptance and separately admitted

## Experimental paired packages

The manually admitted [native packaging workflow](.github/workflows/native-packaging-experiment.yml) builds matching server/worker binaries from its immutable default-branch dispatch SHA. Each Linux/macOS/Windows leg must pass pinned native checks and full release workspace tests, verify the resulting TAR's outer checksum before extraction and every inner checksum/inventory/provenance/source/workflow identity before running the actual extracted paired binaries. The explicit ignored smoke exercises CLI and framed navigation with empty PATH and no Java-home variables, retaining its bounded decoded receipt in a separate evidence ZIP. Default workspace CI does not exercise that archive test; manual execution requires separate ROOT admission.

Only successful extracted smoke permits experimental package upload. A successful leg does not certify the whole matrix, general platform support or full parity; no first-party license grant is invented. Build-child/stripping failures are not accepted merely because Cargo returns zero. See [provider and archive limits](crates/ktlsp-server/README.md) and [source and execution gates](docs/status/development.md#saved-continuation-integration-324). #96 and the unexplained original Windows failures tracked in #377 remain separate open limits.
